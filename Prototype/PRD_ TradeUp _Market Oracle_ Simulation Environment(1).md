# **PRD: TradeUp "Market Oracle" Generative Engine**

## **1\. Product Overview**

The **Market Oracle** is a unified simulation environment that transforms real historical PSX data into "Future Scenarios." Instead of real-time multi-agent chaos, it uses a **Tri-Agent Pipeline** to script, narrate, and execute 30-day market windows.

### **Key Innovations:**

* **The Scenario Library:** New generation results are stored in the database. When a user picks a preset (e.g., "IMF Default"), they are usually "replaying" a high-quality, pre-cached state, saving LLM costs.  
* **Dual-Tier Utility:** Beginners play through "Scripted Presets" to learn mechanics. Pros use the "Realistic Outlook" preset, which synthesizes live global/local news into a projected 30-day forecast.

## **1\. The "Oracle" Library System Design**

### **A. Persistent State Logic**

Instead of generating a new simulation for every user click, the backend will check for an existing, valid `SimulationState` in the database:

1. **Check Cache:** `SELECT * FROM SimulationState WHERE type = :preset AND symbol = :symbol AND createdAt > :expiry`.  
2. **Conditional Generation:** If no state exists, the **Gemini Architect** generates the trajectory, and the **Chronicler** generates the news.  
3. **Store & Serve:** The result is saved as a JSON blob, allowing any user to "replay" that specific 30-day window.

### **B. Benefit for Experienced Traders**

For pros, the **"Realistic Outlook"** preset acts as a **Predictive Analyst**:

* **Live Context Injection:** The system fetches real-time global news (e.g., US Fed rates) and local PSX news (e.g., SBP policy).  
* **Gemini Analysis:** The LLM synthesizes this into a projected 30-day "best-guess" trajectory based on historical patterns of how the PSX reacts to similar news.

## **3\. System Architecture & The Tri-Agent Pipeline**

The system uses **Gemini 1.5 Flash** (for cost/speed) to run three distinct logical passes.

### **A. The Agent Trio**

1. **The Architect (Scenario Designer):** \* **Input:** User selection (Preset) \+ Base Historical Price.  
   * **Output:** A JSON "Trajectory Map" (30 points of percentage modifiers).  
2. **The Chronicler (News Generator):** \* **Input:** The Trajectory Map.  
   * **Output:** 10-15 localized PSX headlines (e.g., "SBP raises rates," "KSE-100 hits record low") that explain the price movement.  
3. **The Executor (Price Engine):** \* **Input:** Trajectory Map \+ Real Historical Data.  
   * **Logic:** $P\_{synth}(t) \= P\_{historic}(t) \\times (1 \+ \\text{Architect\\\_Mod}(t))$.

### **The Tri-Agent System Prompts**

You will use these specific system prompts for your Gemini API calls. Each agent is designed to be highly focused and return structured JSON for easy backend parsing.

### **Agent 1: The Architect (Trajectory Designer)**

**Role:** To determine the mathematical path of the stock prices over 30 "ticks" (days).

**System Prompt:** "You are the 'TradeUp Architect,' a senior financial quantitative analyst specializing in the Pakistan Stock Exchange (PSX). Your goal is to generate a 30-day market trajectory based on a specific scenario.

**Input:** A Scenario Type (e.g., Flash Crash, IMF Deal, Realistic Outlook) and a Stock Symbol. **Context:** If the type is 'Realistic Outlook,' you will be provided with current news headlines. **Task:** Generate a JSON array of exactly 30 floating-point numbers. Each number represents the percentage change from the *original* base price (e.g., 1.05 means \+5%, 0.85 means \-15%). **Rules:**

1. The numbers must follow a logical sequence (e.g., a crash shouldn't be a single drop but a volatile downward trend).  
2. Ensure the volatility matches the scenario severity.  
3. DO NOT return text. Return ONLY the JSON array."

### **Agent 2: The Chronicler (Narrative Generator)**

**Role:** To create the "reasons" behind the numbers generated by the Architect.

**System Prompt:** "You are the 'TradeUp Chronicler,' a financial journalist for the KSE-100 index.

**Input:** A JSON array of 30 price modifiers from the Architect. **Task:** Generate a JSON object containing exactly 10 headlines. Each headline must be mapped to a specific 'day' (index 0-29) within the simulation. **Tone:** Use professional, localized Pakistani financial terminology (mentions of 'SBP,' 'Capital Gains Tax,' 'Circular Debt,' 'Dividend yield'). **Constraint:** The headlines must correlate with the price action. If the price is dropping significantly on Day 5, generate a headline explaining why (e.g., 'Inflation spikes to 24%, sparking sell-off in banking sector')."

### **Agent 3: The Executor (Outcome Summarizer)**

**Role:** To analyze the user's performance after they finish the simulation.

**System Prompt:** "You are the 'TradeUp Executor.' Your job is to provide a post-mortem analysis of a trader's performance during a 30-day simulation.

**Input:** The user's initial balance, final balance, and a log of their transactions. **Task:** Provide a brief (3-sentence) summary.

1. Evaluate their risk management.  
2. Identify if they successfully 'timed' the scenario events.  
3. For experienced traders, provide one technical tip based on their trading frequency and P\&L. **Tone:** Encouraging but realistic."

### **B. The Persistence (Reuse) Layer**

To avoid repeating LLM calls, every generated scenario is saved as a **SimulationState**.

* **Shared States:** If 100 users select "The Flash Crash," they all use the *same* pre-generated trajectory and news feed stored in PostgreSQL.  
* **The "Oracle" Refresh:** The "30-Day Oracle" (Pro) is refreshed once every 24 hours. The first person to request it each day triggers the LLM; everyone else that day uses the cached result.

## **4\. Technical Stack**

| Layer | Technology | Status |
| :---- | :---- | :---- |
| **LLM API** | **Gemini 1.5 Flash** | Chosen for 15x lower cost than Pro and sub-second latency. |

## **5\. Execution Plan (Step-by-Step)**

### **Step 1: Database Migration & Schema (Immediate)**

* **Action:** Add SimulationScenario model to Prisma.  
* **Fields:** presetType (Enum), stockSymbol, trajectoryJson (The 30-day percentages), newsJson (The headlines), expiresAt.

### **Step 2: The "Architect" Prompting (Backend)**

* **Action:** Implement the Gemini Service.  
* **Logic:** Create a function getScenario(type, symbol). It first checks the DB for a non-expired state. If null, it calls Gemini to generate a new 30-day "Future History" and saves it.

### **Step 3: The "Oracle" Frontend (UI)**

* **Action:** Create app/oracle/page.tsx.  
* **Feature:** A simple grid of the 4 Presets.  
* **Feature:** A "Play" mode that uses a JS setInterval to "stream" the stored 30-day data from the DB to the chart every 5-10 seconds.

### **Step 4: Pro Mode Integration (Final)**

* **Action:** Hook the "30-Day Oracle" into your existing news/latest and news/stock services.  
* **Logic:** Pass the current actual news into Gemini as context for the "Architect" to generate a "Realistic" trajectory.
